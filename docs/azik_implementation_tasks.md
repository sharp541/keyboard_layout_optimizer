## タスク詳細

### T01 拡張トークン定義と共通ユーティリティ追加

- Status: `DONE`
- 目的: 専用トークンの知識を散らさず 1 箇所にまとめる
- 作業項目:
- 9 種の拡張トークン一覧を定義する
- 各トークンに内部 `char` と表示ラベルを割り当てる
- `ann` などの拡張トークンかどうかを判定できるようにする
- 通常母音、通常子音を判定できるようにする
- 完了条件:
- 任意の内部 `char` から `ann` などの表示名を引ける
- 通常文字か拡張トークンかをコード上で判定できる

### T02 日本語前処理器の実装

- Status: `TODO`
- 目的: 日本語コーパスを専用トークン入り列へ正規化する
- 作業項目:
- 左から最長一致のスキャナを実装する
- 直前が通常子音のときだけ `ann/inn/unn/enn/onn/ai/uu/ei/ou` を置換する
- それ以外は通常文字をそのまま出力する
- 完了条件:
- `kannzi -> k + <ann> + z + i`
- `tou -> t + <ou>`
- `kannou -> k + <ann> + o + u`
- 上記がテストで固定されている

### T03 n-gram DB 生成時に source ごとの前処理を適用

- Status: `TODO`
- 目的: 日本語だけ前処理し、英語は現状維持で DB 化する
- 作業項目:
- `NGramDB::new` で source ごとの前処理フックを追加する
- source 名と前処理規則の対応を整理する
- DB 生成時の 1-gram / 3-gram 集計が前処理済み文字列に対して動くことを確認する
- 完了条件:
- 日本語 source は専用トークンを含む n-gram を生成する
- 英語 source は専用トークンを含まない

### T04 拡張付きキー表現の導入

- Status: `TODO`
- 目的: 「通常文字配置」と「子音キーにぶら下がる拡張」を分離して保持する
- 作業項目:
- 現在の `char -> key index` モデルを拡張できる構造にする
- 子音キーのみ拡張割当可能という制約を表現する
- 1 キー 1 拡張を保証する
- 母音キーには拡張を割り当てられないようにする
- 完了条件:
- 任意の通常文字は従来どおり 1 キーに割り当てられる
- 任意の拡張トークンは親子音キーに解決できる

### T05 拡張付きキーの検索・評価 API 実装

| --- | --- |
| Status | `TODO` / `DOING` / `BLOCKED` / `DONE` のいずれかに更新する |
